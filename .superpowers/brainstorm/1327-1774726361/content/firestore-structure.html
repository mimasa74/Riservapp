Struttura documento Firestore — opzione B

Un documento per specie. Esempio: /species/cervo

/species/cervo {

  anno: 2026,

  note: "I GIORNI DI CACCIA SONO: MERCOLEDÌ E SABATO...",
  alert: "SABATO 29 MARZO 2026 CACCIA CHIUSA",

  updatedAt: Timestamp,

  categories: [
    {
      id:             "ce1",          // fisso
      nome:           "PALCUTI",      // fisso
      descrizione:    "(anni 2 e più)", // fisso
      badgeChiusura:  "CHIUSI",       // fisso
      totale:         6,             // cambia a inizio stagione
      abbattuti:      6,             // cambia durante stagione
      stato:          "chiuso"       // "aperto" | "chiuso"
    },
    {
      id: "ce2", nome: "FUSONI", totale: 4, abbattuti: 1, stato: "aperto", ...
    },
    // ... FEMMINE, PICCOLI
  ]
}

Il Camoscio ha le zone

/species/camoscio {

  anno: 2026,
  penalita: "YARLING ASSEGNATI PER PENALITÀ: COVA SAMUELE",
  note: "...",
  alert: "...",
  updatedAt: Timestamp,

  zone: {
    campa: {
      categories: [ /* 6 categorie */ ]
    },
    tovel: {
      categories: [ /* stesse 6 categorie, dati indipendenti */ ]
    }
  }
}

Le altre collezioni

/bacheca/{postId}  → un documento per post

/ruote/{turnoId}   → un documento per turno
  { specie_id, nome, data }

Aggiornamento tipico: il Rettore tocca un quadratino → updateDoc("/species/cervo", { "categories": [...array aggiornato...] })
Tutti i dispositivi connessi vedono la modifica in tempo reale.
